## Shared Types
- `SectionConfig`: `{ id: string, init: () => void, cleanup: () => void }` - Defines the lifecycle contract for each interactive section.
- `AudioManager`: `{ play: (id: string, loop?: boolean) => void, stop: (id: string) => void }` - Centralized audio control interface.
- `AnimationManager`: `{ animate: (selector: string, keyframes: Keyframe[], options?: KeyframeAnimationOptions) => void }` - Centralized SVG/CSS animation control interface.
- All section modules must conform to `SectionConfig` and register via `engine.js`.

## API Contract
- `engine.js` is the single source of truth for cross-cutting concerns. It exports `initSite()`, `registerSection(config: SectionConfig)`, `audio: AudioManager`, and `anim: AnimationManager`.
- Section files (`js/sections/*.js`) must import `registerSection` from `engine.js`, instantiate a `SectionConfig` object, and call `registerSection`. They must NOT import from each other.
- `index.html` must load `engine.js` first, followed by all section scripts in DOM order. It must not contain inline logic.
- CSS must use `:root` variables defined in `main.css`. No global resets or base styles outside `main.css`.
- SVG elements must have `id` attributes that exactly match the `selector` string passed to `anim.animate()`.
- Audio files must be placed in `assets/audio/` and referenced by `snake_case` IDs matching `audio.play()` calls.

## Naming Conventions
- JS: `camelCase` for functions/variables, `PascalCase` for types/interfaces.
- CSS: `kebab-case` for class names, `--var-name` for custom properties.
- HTML IDs: `kebab-case` matching section names (e.g., `#mars-overview`).
- Audio IDs: `snake_case` matching asset filenames (e.g., `wind_howl`).
- SVG IDs: `camelCase` matching JS selectors (e.g., `planetOrbit`).
