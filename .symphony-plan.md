## Shared Types

These types are used across all modules. All JavaScript objects that conform to these shapes must use the property names exactly as specified (camelCase).

### Medication
```typescript
type Medication = {
  id: string;          // unique identifier, generated via crypto.randomUUID()
  name: string;        // e.g., "Aspirin"
  dosage: string;      // e.g., "100mg"
  schedule: Schedule;
};
```

### Schedule
```typescript
type ScheduleType = 'daily' | 'weekly' | 'custom';
type Schedule = {
  type: ScheduleType;
  times: string[];     // array of "HH:MM" (24h), e.g., ["08:00", "20:00"]
  days?: number[];     // for 'weekly' or 'custom': 0=Sun, 1=Mon, …, 6=Sat
};
```

### Dose
```typescript
type Dose = {
  id: string;          // unique identifier
  medicationId: string; // FK to Medication.id
  scheduledTime: Date; // Date object (JS)
  taken: boolean;      // false by default
  takenAt?: string;    // ISO 8601 string if taken
};
```

### HistoryEntry (used for display/logging)
```typescript
type HistoryEntry = {
  doseId: string;
  medicationName: string;
  takenAt: string;     // ISO 8601 string
};
```

## API Contract (Module Interfaces)

All modules register themselves on the global `window` object under a dedicated namespace. The integrator (`main.js`) and other modules access each other through these namespaces. Namespaces:

- `MedRemMedications` – medication storage
- `MedRemSchedule` – schedule computation
- `MedRemLogging` – dose-taking history
- `MedRemNotifications` – browser notification & sound

Each namespace is an object exposing the functions listed below.

### 1. Medications Module (`medications.js`)

- `MedRemMedications.initMedications(storageKey: string): void`
  - Initialises the store using `localStorage` key `storageKey`. Must be called once before any other medication operation.

- `MedRemMedications.addMedication(medication: Medication): Medication`
  - Adds a new medication to the store. Assigns an `id` if missing. Returns the stored medication (with id).

- `MedRemMedications.getMedications(): Medication[]`
  - Returns all stored medications.

- `MedRemMedications.removeMedication(id: string): void`
  - Removes the medication with the given id. No effect if id doesn't exist.

### 2. Schedule Module (`schedule.js`)

- `MedRemSchedule.getUpcomingDoses(medications: Medication[]): Dose[]`
  - Given a list of medications (e.g., from `getMedications()`), computes all scheduled doses that have not yet been taken or are upcoming within a configurable look‑ahead window (default: 24 hours). Returns an array of `Dose` objects sorted by `scheduledTime` ascending. The `taken` flag is always `false`. The caller is responsible for checking against logged history.

### 3. Logging Module (`logging.js`)

- `MedRemLogging.initLogging(storageKey: string): void`
  - Initialises the history store using `localStorage` key `storageKey`. Must be called once before any logging operation.

- `MedRemLogging.markDoseTaken(doseId: string): void`
  - Records that the dose with the given id has been taken. Stores a `HistoryEntry` with the current timestamp. No‑op if the doseId is already taken (avoids duplicates).

- `MedRemLogging.getHistory(): HistoryEntry[]`
  - Returns all logged history entries, newest first.

### 4. Notifications Module (`notifications.js`)

- `MedRemNotifications.initNotifications(): void`
  - Requests browser notification permission if not already granted. Sets up an interval (every 30 seconds) that calls `checkAndNotify` with the current list of upcoming doses (obtained from the schedule module).

- `MedRemNotifications.checkAndNotify(doses: Dose[]): void`
  - Compares each dose's `scheduledTime` with the current time. If it is within the notification threshold (default: at exact time ± 30 seconds), triggers a browser notification and plays a short audio sound (sound file to be provided by integrator).
